# Принятые решения и открытые вопросы

Обновлено: 2026-11-13
Связанный документ: [MIGRATION_PLAN.md](MIGRATION_PLAN.md)

Формат: решение, статус, обоснование. Статусы: «Принято», «Ожидает подтверждения»,
«Отложено».

## Принято

### D-001. Android-разработка ведётся в Android Studio

Статус: Принято (подтверждено пользователем 2026-11-13)

Проект `android/` создаётся и открывается в Android Studio. Это отдельный
Gradle-проект со своим wrapper и Android Gradle Plugin; он не включается в
корневой `settings.gradle`, чтобы не конфликтовать со сборкой backend.

### D-002. Миграция по стратегии strangler

Статус: Принято

REST API добавляется рядом с Vaadin. Vaadin остаётся рабочим до достижения
паритета web и Android. Удаление Vaadin — отдельный финальный этап.

### D-003. Единый REST API для web и Android

Статус: Принято

Базовый путь `/api/v1`. Контракт описывается через OpenAPI. Клиенты (web и
Android) генерируют типы/клиентов из одного контракта.

### D-004. Нормализация переводов строк

Статус: Принято и выполнено (2026-11-13)

- В репозитории хранится LF: `.gitattributes` с `* text=auto eol=lf`.
- Исключения: `*.bat`, `*.cmd` — CRLF; `gradlew` — LF.
- Бинарные расширения помечены `binary`.
- Локально выставлен `core.autocrlf=false` (только для этого репозитория).
- Рабочее дерево перечитано с LF, `git status` чистый.

### D-005. Структура репозитория

Статус: Принято

```text
bot/       # backend (домен + REST + временно Vaadin)
web/       # React SPA
android/   # Android-приложение (Android Studio)
docs/      # план, решения, контракт API
```

Переименование `bot` -> `backend` — в конце миграции (Этап 4), чтобы не ломать
историю и сборку.

## Ожидают подтверждения

Ниже — рекомендуемые значения по умолчанию. Если пользователь не изменит их,
они считаются принятыми при старте соответствующего этапа.

### D-006. Web-стек

Статус: Ожидает подтверждения (по умолчанию принято)

React 19 + TypeScript + Vite + React Router + Mantine + TanStack Query +
React Hook Form + Zod. Обоснование: Vaadin 25 уже использует React 19,
большая экосистема, быстрый старт, удобные таблицы и формы.

### D-007. Android-стек

Статус: Ожидает подтверждения (по умолчанию принято)

Kotlin + Jetpack Compose + Material 3 + Hilt + Retrofit/OkHttp +
kotlinx.serialization + DataStore/EncryptedSharedPreferences.
minSdk 26, актуальные compile/target SDK.

### D-008. Аутентификация

Статус: Принято и реализовано (2026-11-16)

JWT: access 15 минут, refresh 30 дней (соответствует текущей 30-дневной сессии).
Refresh-токен хранится в БД в виде SHA-256 хеша, ротация при refresh, отзыв при
logout. Web: access в памяти, refresh в HttpOnly cookie. Android: оба
токена в защищённом хранилище. `/auth/refresh` принимает refresh из cookie или
из body. Секрет подписи — `JWT_SECRET` (dev-значение по умолчанию в
`application.yml`, для production задавать обязательно).

### D-009. Раздача web SPA

Статус: Ожидает подтверждения (по умолчанию принято)

SPA собирается и раздаётся тем же Spring Boot приложением (static resources),
API — на том же origin. Во время миграции SPA доступна на `/app`, Vaadin — на `/`.
Отдельный static-хостинг (Nginx/Vercel) не требуется.

### D-010. Объём v1

Статус: Ожидает подтверждения (по умолчанию принято)

В v1 не добавляем: офлайн-режим, push-уведомления, регистрацию/создание
пользователей, мультивалютность. Только паритет с текущим Vaadin-приложением.

### D-011. Валюта и локаль

Статус: Ожидает подтверждения (по умолчанию принято)

Только RUB, локаль `ru-RU`, даты `dd.MM.yyyy`. В API передаются числа и
`LocalDate`/ISO-даты, форматирование — на клиентах.

### D-012. Публикация Android

Статус: Ожидает подтверждения

Достаточно ли APK / Google Play Internal testing, или нужен полноценный
релиз в Google Play? По умолчанию: APK + Internal testing, без публичного релиза.

### D-013. Контракт API и springdoc

Статус: Ожидает подтверждения (по умолчанию принято)

Контракт ведём annotation-first через springdoc-openapi, генерируем `openapi.json`
и клиентов из него. Если springdoc окажется несовместим со Spring Boot 4 —
переходим на contract-first: `docs/api/openapi.yaml` как источник истины.

## Отложено

- Переход на `Instant`/UTC и использование `User.userZone` (после миграции,
  отдельной задачей).
- Офлайн-кеш и фоновая синхронизация в Android.
- Push-уведомления.
- Мультивалютность.
- Публичный релиз в Google Play.
